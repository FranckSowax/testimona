Testimona est une application de gestion de pages mémorielles. Elle permet de créer des mémoriaux, des témoignages, biographies, funérailles, photos et donations (Stripe). L'application nécessite une mise à niveau majeure avant production : frameworks obsolètes, vulnérabilités de sécurité, dette technique importante, et absence totale de tests.
● Mise à jour 2026-05-06 — État de remédiation
Le backend est largement modernisé ; le frontend reste sur la stack legacy
Une revue ciblée du code source révèle que la quasi-totalité des correctifs de sécurité critiques du Plan Phase 1 ont été appliqués côté API : helmet, express-rate-limit, bodyParser avec limite 1MB, redirection HTTPS, Swagger gated en prod, cookies sameSite durci, JWT enrichi issuer/audience, et surtout le hachage des mots de passe migré de AES symétrique vers bcrypt (12 rounds) avec helper isLegacyPassword pour migration progressive. La Phase 2 backend est également faite : Express 4.21, Prisma 6, axios 1.7, cloudinary 2, stripe 17, google-auth 9, redis 4.7, TypeScript 5.7, ESLint 9, @types/* dans devDependencies. La conteneurisation existe (Dockerfiles multi-stage Node 22 + docker-compose postgres/redis/api/web). Winston est en place pour les logs ; un /health endpoint et un globalErrorHandler sont actifs.

Restent en attente : toute la migration frontend (Angular 15→19, RxJS 6→7, Protractor→Playwright, NgModules→standalone, toPromise()→firstValueFrom), la couche tests (zéro .spec.ts côté API et Web), le pipeline CI/CD (.github/workflows absent), l'APM externe (Sentry/Datadog), la séparation des clés JWT (access/refresh/register), un conteneur DI (les getInstance() manuels persistent), et la documentation (READMEs minimaux, pas de CHANGELOG/CONTRIBUTING).

Vulnérabilités de Sécurité

Critique Risques majeurs — Action immédiate requise
  • crypto-js 3.3.0 (frontend) Fait — Bumpé à 4.2.0 côté web/package.json. Plus de CVE connues.
  • Mots de passe chiffrés avec AES symétrique crypto.service.ts Fait — Migré vers bcrypt (12 rounds). Helper isLegacyPassword() détecte les anciens hash et permet le rehash transparent au login. decryptLegacyPassword() conservée pour migration.
  • Clés de chiffrement dans les variables d'environnement À traiter — Toujours via env vars. .env.example est en place mais aucune intégration vault/Secrets Manager.
  • Fichier .env vide en production api/.env Fait — Un .env.example documenté (953 B) liste désormais toutes les variables requises (DB, Redis, JWT, encryption, Cloudinary, Google, Stripe, mail, log).
  • trust proxy = 1 sans validation app.ts:25 Partiel — Toujours présent, justifié pour reverse-proxy. À valider sur la cible déploiement (un nombre exact de hops est plus sûr qu'un booléen).
Haute Risques importants — À corriger rapidement
  • console.log(error) partout Partiel — Winston logger en place dans logger.service.ts + error.middleware.ts (asyncHandler, globalErrorHandler). Mais jwt.service.ts conserve encore 6 console.log(error) (lignes 45, 81, 99, 116, 136, 178) à remplacer.
  • JWT token key unique À traiter — Toujours Constantes.TokenKey pour register et access. Amélioré : issuer: 'testimona-api' + audience: 'testimona-web' ajoutés. Reste à scinder en 3 secrets distincts.
  • Pas de rate limiting Fait — express-rate-limit appliqué sur /auth et /register (15 min, max 20 req).
  • Pas de helmet.js Fait — helmet() activé en tête de chaîne dans app.ts:17.
  • CORS whitelist fragile À traiter — Toujours WHITELIST_URL.split('|') sans validation d'origine. Inchangé.
  • Cookie sameSite: 'none' Fait — Désormais sameSite: 'strict' si secure, sinon 'lax' (jwt.service.ts:189-196). HttpOnly conservé.
  • API RxJS dépréciée À traiter — Frontend toujours sur RxJS 6.6 — throwError(new Error()) et toPromise() partout. Phase 2 frontend non démarrée.
  • Pas de validation CSRF À traiter — Toujours absent côté API. Atténué partiellement par cookies sameSite: strict, mais token CSRF pour les actions état-changeantes manque.
  • Social login commenté À traiter — Frontend non revu ; @abacritt/angularx-social-login toujours dans web/package.json. À nettoyer ou réactiver proprement.
Moyenne Risques modérés — À planifier
  • Pas de Content Security Policy (CSP) Partiel — helmet() applique les CSP par défaut (script-src 'self', etc.) mais aucune politique custom n'est définie pour les domaines tiers (Cloudinary, Stripe, Google).
  • Swagger UI exposé en production /api/testimona/v1 Fait — Désactivé via if (process.env.NODE_ENV !== 'production') dans app.ts:68.
  • bodyParser.json() sans limite de taille Fait — Limite 1mb appliquée à express.json() et express.urlencoded() (app.ts:20-21).
  • Pas de timeout sur les requêtes HTTP À traiter — Frontend non revu.

Problèmes d'Architecture

Backend

  • Pattern Singleton manuel sur tous les services (getInstance()) au lieu d'un conteneur DI. À traiter — Inchangé : JwtService, RedisService, CryptoService, LogService, StripeService conservent leur getInstance() manuel.
  • @types/* dans dependencies au lieu de devDependencies package.json:28-38. Fait — Tous les @types/* sont désormais correctement dans devDependencies.
  • executeQueries<T> wrapping inutile de Prisma — complexité sans valeur. À vérifier — Pas re-vérifié dans cette mise à jour.
  • Duplication decryptPassword / decryptAnswer Fait — decryptPassword remplacé par verifyPassword bcrypt. decryptAnswer conservé pour les questions de sécurité (cas d'usage légitime distinct).
  • var utilisé dans app.ts Fait — app.ts est désormais 100 % import/const. Plus aucun var.
  • require() mixé avec import dans app.ts Fait — Imports unifiés en ESM-style.
  • Pas de gestion centralisée des erreurs Fait — middlewares/common/error.middleware.ts fournit asyncHandler + globalErrorHandler avec logging Winston. À déployer dans tous les controllers.
  • Promise<any> À traiter — Toujours présent (ex. jwt.service.ts). Migration vers types Prisma générés non amorcée.
  • shadowDatabaseUrl dans schema.prisma Fait — Absent du schéma actuel.
  • Pas de migrations versionnées Fait — 39 migrations versionnées sont présentes dans prisma/migrations/ (depuis 2021-05).

Frontend

  • Angular 15 avec NgModules À traiter — Inchangé. Migration 15→19 non démarrée.
  • toPromise() déprécié dans HttpSharedService À traiter — Confirmé : configuration.service.ts, configuration.datastore.service.ts et autres conservent .toPromise().
  • Pattern datastore custom au lieu de NgRx/signals — 43 services. À traiter Inchangé.
  • window.console.log = () => {} dans main.ts Fait — Le main.ts ne contient plus que enableProdMode() + bootstrapModule. La suppression console est retirée.
  • Pas de lazy loading Public/Admin Partiel — core-routing.module.ts utilise loadChildren pour les sections principales. Reste à découper plus finement.
  • 60+ déclarations dans PublicModule À traiter — Inchangé.
  • environment.prod.ts minimal Fait — Contient désormais apiUrl, assetUrl, donation, googleProvider, publicKey. Reste à externaliser via .env au build pour éviter de committer les URLs.
  • Pas de service worker À traiter — Inchangé.
  • Pas de SSR/SSG À traiter — Inchangé. server.js reste un serveur Express statique de bundles.
